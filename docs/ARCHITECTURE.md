# LunaSieve 架构说明

## 目标

LunaSieve 面向日志管道、API 网关、配置检查和 CI 审计等基础设施场景。核心目标是可组合、默认不泄密、跨运行目标可用，并保持检测与宿主 I/O 解耦。

## 数据流

```text
输入文本 / 文档集合
        │
        ├── 前缀目录检测
        ├── 结构化格式检测
        ├── 配置键上下文检测
        ├── PEM 与连接串检测
        └── 高熵启发式检测
                  │
            排序与重叠消解
                  │
        ┌─────────┼─────────┐
      白名单    脱敏策略   位置映射
        └─────────┼─────────┘
          文本 / JSON / SARIF
```

## 检测与优先级

确定性规则优先于启发式规则。相同位置发生重叠时，供应商前缀、JWT、证件和上下文规则优先于高熵结果；同类结果再按严重程度和置信度排序，避免将 `ghp_...` 仅报告为“高熵字符串”。

配置键使用单词边界和赋值符约束，不会因为文档中出现 `password` 一词就报警。连接串只在 URI 中同时存在用户名、密码分隔符和 `@` 时报告。

## 隐私模型

`Finding` 不保存原始匹配内容。预览默认固定为 `[hidden]`，显式启用后也只保留首尾少量字符。JSON、文本和 SARIF 报告只使用安全字段。脱敏需要调用方同时提供原文和 Span，在受控边界内完成。

## 流式模型

`StreamScanner` 在每次 `push` 后保留固定大小的尾部窗口，只发出完整落在稳定区间内的结果。`finish` 扫描最后缓冲区并永久关闭实例。默认窗口为 256 个字符，超过内置固定前缀的最大匹配长度。

## 批量与 CI

批量层接收 `Document(path, content)`，不直接遍历文件系统，避免硬编码权限、符号链接和编码策略。发现结果基于路径、检测器和位置生成稳定指纹，可进行基线过滤。

SARIF 输出遵循 2.1.0 基本结构，包含规则 ID、级别、文件 URI、行列区域和部分指纹，可供 GitHub Code Scanning 或其他兼容工具消费。

## 非目标

- 不管理、存储或轮换真实凭据。
- 不声称启发式扫描可以证明不存在秘密。
- 不在核心库内遍历磁盘或发送网络请求。
- 不使用弱哈希动作替代密码学哈希或密钥派生函数。
